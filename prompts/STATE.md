# Состояние проекта

`docs/project-state.md` — короткий текущий снимок одного сайта, а не журнал разработки и не общий checklist Prompt Kit.

## Чтение

- Сначала проверь размер файла.
- Если он не больше `4096` байт, прочитай целиком.
- Если он больше, не загружай всю хронику: извлеки текущий статус, последний релевантный результат, блокеры, источники и следующий шаг по заголовкам и точечному поиску.
- `docs/project-history.md` открывай только для восстановления старого решения.
- Подтверждение выполненных этапов ищи в указанных артефактах и review-файлах.

## Жёсткий бюджет

- Итоговый `docs/project-state.md` — не более `4096` байт.
- Перед заменой разросшегося снимка сделай резервную копию и без потерь добавь прежний текст в `docs/project-history.md`.
- Не дописывай в снимок завершённые задачи. Оставляй только последний значимый результат.
- Удаляй пустые и неприменимые строки.
- Ссылки заменяют пересказ содержимого документов.
- Состояние и история принадлежат только текущему сайту и не входят в Web Kit Release.

```md
# Состояние проекта

## Сейчас

- Этап: `unknown`
- Уверенность: низкая
- Текущая задача: нет

- Публикация: нет
- CMS: не проверено
- Обновлено: YYYY-MM-DD

- Проверено:
- Подтверждение:

## Блокеры и решения

- Блокеры: нет
- Нужен выбор пользователя: нет
- Открытые решения: нет

## Источники истины

- Причина:
- Нужно подтверждение: нет
```

Можно добавить только применимые короткие флаги: техническая архитектура, application flows, technical SEO или design pass. Их подробные критерии остаются в профильных review-файлах.

## Правила обновления

- Меняй этап только по подтверждающему артефакту или review. Машинные значения этапов вроде `block-build` сохраняй без перевода.
- При низкой уверенности сохраняй прежний этап и укажи один пробел в открытых решениях.
- Для магазина достаточно флага и ссылки на `docs/ecommerce/ecommerce-review.md`.
- Для CMS фиксируй решение из реального редакторского процесса, а не установку «на будущее».
- Для дизайна сохраняй только текущий creator/critic pass и ссылку на профиль или review.
- До render не объявляй полный UI/copy compliance.
- После обновления Prompt Kit не откатывай готовые стадии сайта автоматически.
- Версию кита определяй по `.prompt-kit/manifest.json`; не копируй в снимок данные, которые уже есть в manifest и update-отчёте.
- Не записывай Git remote, branch, commit, secret values, credential paths или персональные данные.
- Следующий шаг должен быть один. Служебный путь к промпту не заменяет человеческого объяснения.
- Сообщение пользователю сверяй с `prompts/_knowledge/codex-user-response-quality.md`.
