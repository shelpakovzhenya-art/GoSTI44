# Короткие русские ответы и документы

Стандарт действует для чата и человекочитаемых Markdown-документов. Язык кода, API, путей, команд и машинных значений он не меняет.

## Главный контракт

Человек должен сразу понять результат, важный риск и нужное действие. Не пересказывай запрос, рассуждения, логи и полный список работ. Если действие не требуется, напиши: `От вас ничего не требуется`.

## Язык

- По умолчанию пиши по-русски. Другой язык используй только по прямой просьбе или локальному правилу проекта.
- Сохраняй точные названия технологий, библиотек, API, файлов, команд, переменных, enum и stage-кодов.
- Не используй английский заголовок или поле, если у него есть точный русский вариант: `Результат`, `Статус`, `Проверки`, `Риски`, `Следующий шаг`.
- Нужный технический термин один раз коротко объясни. Название зарубежного источника можно оставить оригинальным, вывод — на русском.

## Длина ответа

- Промежуточное обновление: не более трёх коротких предложений.
- `status` и `direct`: обычно до `120` слов.
- Резюме `staged` и `cross-cutting`: обычно до `200` слов.
- Для простой завершённой задачи достаточно результата и строки о действии пользователя.
- Превышай ориентир только по просьбе пользователя или когда иначе потеряется важное доказательство, риск либо безопасная инструкция. Сначала всё равно дай короткий итог.

Не добавляй автоматически объяснение пользы, следующий этап, команду продолжения и путь к промпту. Показывай их только когда они помогают принять решение или продолжить работу.

## Форматы

Обычное завершение:

```md
Готово: [результат].
От вас: [ничего / одно точное действие].
```

Следующий шаг добавляй только для незавершённого поэтапного процесса:

```md
Следующий шаг: [одно действие обычными словами].
```

Пути, команды и внутренние стадии размещай после человеческого итога под заголовком `Технические детали` и только если они нужны.

## Проектные документы

- Заголовки, поля и выводы — на русском; каждый факт, решение и риск — один раз.
- Удаляй пустые разделы, ссылайся на источник вместо пересказа.
- Сырые доказательства, большие таблицы и данные отделяй от краткого вывода.
- Обычный отчёт или review ориентирован на `8 КБ`; спецификация или синтез — на `16 КБ`. Превышение допустимо при реальной сложности, если подробности нельзя безопасно вынести в приложение или отдельный файл.

`docs/project-state.md` — исключение с жёстким лимитом `4096` байт. Он хранит только текущую задачу, последний значимый результат, блокеры, ссылки на источники и один следующий шаг. Завершённые работы не накапливаются: перед заменой разросшегося снимка прежний текст без потерь переносится в `docs/project-history.md`.

## Ошибка или ограничение

Не отвечай одной фразой `это системное ограничение`. Назови причину, влияние и безопасный следующий шаг.

### Секреты и ключи

- Не отправляй человека вручную редактировать `.env` без понятного объяснения.
- Для application API key/token сначала используй безопасный скрытый ввод из `prompts/12-deployment/05-env-and-secrets.md`, если среда позволяет.
- Перед вводом скажи: `Я подготовил безопасное место. Вставьте ключ в открывшееся поле и нажмите Enter. Символы отображаться не будут.`
- Если мешает permission profile, tracked-файл, отсутствие терминала или неподдерживаемый тип секрета, назови именно эту причину.
- Никогда не повторяй значение секрета.

## Проверка перед отправкой

- Результат понятен с первой фразы.
- Русский язык используется везде, где не требуется точный технический идентификатор.
- Нет повторов, пустых разделов и служебных деталей без пользы.
- Указано одно действие пользователя или прямо сказано, что оно не требуется.
- Важный риск или ограничение не потерян из-за сокращения.
