# Техническая архитектура — 09.09.2026

## Источник контента

CMS обязательна во всех окружениях: Next.js 16 / React 19 получают опубликованные записи Laravel 12 / Filament 5 через серверный API. `CMS_URL` обязателен. `content/*.json` — только вход первого импорта CMS, не резервный контент сайта. SQLite, пользователи, сессии, загрузки и секреты не входят в Git.

Путь данных: `getEntries` → проверка версии и структуры API → `assembleContent` → типизированный `SiteContent` → `ContentProvider` → компоненты. Серверный fetch использует no-store и объединяется React cache в пределах рендера. При сбое CMS сайт сообщает ошибку; старые данные не возвращаются незаметно.

## Границы модулей

- `src/lib/content-types.ts`: DTO страницы и дома, без значений контента.
- `src/lib/content.ts`: транспорт, проверка API и чистая сборка DTO. Сборка не читает env/JSON и не меняет входные записи.
- `collectionAdapters`: один обработчик на вид коллекции. Дома, услуги, отзывы и вопросы не зависят от фиксированного числа записей.
- `singletonAdapters`: явные ключи настроек, основного меню, галереи, удобств и фотографий. Второе меню не заменяет основное из-за случайного порядка API.
- `CmsText`: текст только из CMS; пустое или отсутствующее значение не подменяется захардкоженной фразой. Изображения используют ключи расположения для замены из CMS; статические пути в шаблонах обозначают расположение/оформление, коллекции содержат собственные фото.
- Предпросмотр использует ту же проверку ответа и тот же сборщик. H1 страницы имеет явный приоритет над текстовым ключом, независимо от порядка записей.

Неизвестные виды записей не выводятся на главной: страницы и redirects обслуживают свои маршруты. Некорректные известные данные отклоняются с диагностикой. Пустая коллекция остаётся пустой, а не восстанавливается из seed. Дом без фото не допускается валидатором CMS и адаптером.

## Расширение

Новый дом/услуга/отзыв/вопрос добавляется в CMS без изменения сборщика или шаблонов. Число домов и подписи в блоке компании используют ту же коллекцию, что карточки. Приблизительность площади — отдельное поле CMS, не условие по цвету/названию дома.

Новый вид данных требует DTO, одного адаптера и его отображения; новый редакторский формат также требует формы и серверной валидации CMS. Новый тип визуального раздела требует компонента: это сайт с разработанными шаблонами, а не универсальный конструктор произвольной разметки. Не создавать второй сборщик или параллельные списки тех же сущностей. Ключи существующих текстов/изображений менять только с миграцией опубликованных и черновых записей.

## Редактирование и права

Редактор сохраняет черновик; публикация выполняется отдельно. Роли, блокировка аккаунтов, signed preview, очистка HTML и история версий проверяются на сервере. Внешний ReservationSteps отвечает за доступность и бронирование; CMS не принимает платежи.

## Runtime

Next standalone под systemd, Nginx и PHP 8.4 FPM в Docker. Сайт и CMS используют https://tangerin.a-test.ru; www и HTTP перенаправляются на основной HTTPS-адрес. Livewire имеет версионный префикс: proxy должен пропускать `/livewire-<hash>/`, включая JS, update и upload, а не только `/livewire/`. Laravel получает HTTPS-признак от внутреннего прокси, cookies Secure включены.

Индексация пока выключена. Домен не является разрешением включить её. Эксплуатация, постоянные данные, сертификат и откат: [runbook](../deployment/deploy-runbook.md).

## Регрессионные проверки

`npm run verify:content` проверяет реальные адаптеры: пустые/удалённые коллекции, новые записи и порядок, отсутствие мутации/общих объектов, H1, дубли ключей, неверный API и отсутствие CMS_URL. `typecheck`, `lint` и production build проверяют frontend.

`php artisan test` проверяет черновик → публикацию → восстановление, права, signed preview, HTML, media/export и настоящий вход Filament по alias с верным/неверным паролем. Браузерная проверка отдельно покрывает вход/выход и показ пароля, загрузку контента, desktop/mobile и интерактивные элементы сайта. Один HTTP 200 больше не считается проверкой работоспособности админки.
