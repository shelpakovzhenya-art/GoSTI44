# Техническая архитектура — 08.09.2026

## Решение
Пользователь явно выбрал Filament и редактирование без кода. Переходим от статического экспорта к Next.js server runtime + отдельному Laravel CMS. Next 16.3.4 и React 19.2.8 сохраняются. Laravel 12, PHP 8.2+, Filament 5; точные зависимости фиксируются lockfiles.

## Контент
CMS в каталоге cms/. SQLite локально, совместимая SQL БД на сервере. Страницы, структурированные блоки, дома, медиа, меню, контакты, отзывы, SEO и перенаправления. Редактор сохраняет черновик; публикация отдельным действием. Роли администратора и редактора, история изменений и восстановление. Визуальный и HTML режимы одного содержимого, серверная очистка HTML. Загрузка изображений с проверкой типа и размера, alt и подписью.

Next получает только опубликованные DTO через серверный API. Черновики и пользователи никогда не входят в публичный API. Начальные данные и разрешённые фотографии входят в репозиторий; рабочая БД, секреты и пользовательские сессии исключены. Сбой CMS не должен незаметно подменять опубликованный контент стартовыми данными на production.

## Runtime и эксплуатация
Локально два процесса: Next 3107 и Laravel 8107. Production: Node и PHP-FPM за reverse proxy, постоянные БД и uploads, резервные копии. Конкретный сервер и домен отложены. Canonical/sitemap используют настроенный origin; без него локальная индексация запрещена. Бронирование остаётся внешним ReservationSteps: CMS не принимает платежи и не управляет наличием мест.

## Проверки
Build/lint/types frontend; backend тесты публикации, прав доступа, HTML, медиа и SEO. Браузер: вход CMS, изменение черновика, публикация на сайте, фотографии и восстановление; PC/mobile, меню, галерея, бронирование, карта. Чистая установка из репозитория и восстановление данных. Все проверки фиксируются по фактическому результату.

Официальная документация: https://filamentphp.com/docs/5.x/introduction/installation ; https://laravel.com/docs/12.x .
