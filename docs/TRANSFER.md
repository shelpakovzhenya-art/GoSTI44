# Перенос на другой компьютер и резервные копии

## Начальная версия из GitHub

Клонирование репозитория переносит код, исходные фотографии, стартовый контент, миграции и lockfiles. Выполните первый запуск из README. Учётные записи и секреты создаются на новом устройстве и не хранятся в Git.

## Перенос текущих изменений CMS

Git не содержит рабочую SQLite и новые uploads. Перед сменой компьютера из каталога cms создайте архив по новому пути:

```powershell
php artisan cms:export D:\Codex\temp\tangerine-content-20260908.zip
```

Архив содержит опубликованный контент, черновики, версии и загруженные фотографии. В нём нет пользователей, паролей и APP_KEY. Не публикуйте архив: черновики могут быть непубличными.

На втором компьютере выполните установку зависимостей, key:generate и migrate, но НЕ запускайте SiteContentSeeder. Затем:

```powershell
php artisan cms:import D:\Codex\temp\tangerine-content-20260908.zip
php artisan storage:link
php artisan cms:admin
```

Импорт разрешён только в пустую базу контента и не перезаписывает существующие фотографии. Для восстановления старой копии создайте отдельную установку, проверьте её и затем переключите сайт. Не удаляйте рабочую базу ради импорта. Архивы свыше 1 ГиБ требуют отдельного контролируемого восстановления.

## Полная эксплуатационная копия

Для сохранения пользователей и сессий дополнительно нужен согласованный снимок БД (SQLite backup/VACUUM INTO либо штатный дамп серверной SQL БД), storage/app/public и cms/.env с APP_KEY. Такой снимок содержит секреты и хранится отдельно с ограниченным доступом. Не копируйте открытую SQLite простым файловым копированием во время записи.

Проверяйте восстановление в отдельной установке: вход, контент, черновики, публикация, фото и доступность сайта. Наличие ZIP само по себе не подтверждает восстановление.
