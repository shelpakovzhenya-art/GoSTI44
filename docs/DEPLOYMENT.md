# Развёртывание

Production-сервер и домен не назначены. Ниже схема установки, а не отчёт о состоявшемся деплое.

## Сервисы

- Node.js обслуживает Next.js server runtime.
- PHP-FPM обслуживает Laravel из cms/public.
- Reverse proxy маршрутизирует /admin, /livewire, /api/content, /storage и assets Filament к Laravel; сайт — к Node. Можно вынести CMS на отдельный поддомен и указать его в CMS_URL.
- БД и cms/storage/app/public находятся на постоянном диске. Не заменяйте их при выпуске новой версии.

## Выпуск

Установите зависимости по lockfiles: npm ci и composer install --no-dev --optimize-autoloader. Задайте Laravel APP_ENV=production, APP_DEBUG=false, APP_URL с HTTPS, SESSION_SECURE_COOKIE=true, корректную БД и секретный APP_KEY. Секреты не коммитятся. Выполните миграции, storage:link, filament:assets, config:cache и route:cache. Начальный SiteContentSeeder запускается один раз на новой установке; текущие данные переносятся архивом.

Frontend: задайте CMS_URL, соберите npm run build. Для standalone скопируйте public и .next/static в соответствующие каталоги .next/standalone, затем запускайте node .next/standalone/server.js под менеджером процессов. PORT/HOSTNAME задаются окружением. Либо обслуживайте полную установленную рабочую директорию через next start. PHP встроенный dev-сервер для production не используется.

Прокси должен отдавать правильные forwarded headers только от доверенного адреса; настройте Laravel trusted proxies под выбранную инфраструктуру. Ограничьте upload body 20 МиБ на прокси/PHP, в CMS лимит фото 15 МиБ. Настройте сохранение логов, мониторинг /up и резервные копии.

## До открытия индексации

Проверить бронирование без реального платежа, фото, мобильное меню, карты, форму входа и права, публикацию/восстановление. Сверить адрес 47/45А и старое название во внешних карточках/ReservationSteps с клиентом. Подключить юридические материалы и аналитику после получения данных. Далее выполнить [SEO.md](SEO.md).

## Откат

Сохраняйте предыдущую версию кода, миграционный план и проверенный снимок данных. При проблеме переключите код на прежний выпуск; миграции не откатывайте вслепую. При необходимости восстанавливайте данные в отдельную БД и проверяйте перед переключением. Не удаляйте текущую установку до проверки восстановления.
